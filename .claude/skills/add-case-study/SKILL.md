# Add a case study

Customer success stories live in the same MDX collection machinery as blog
posts — this skill is the case-study sibling of **add-blog-post**. If you're
comfortable with that skill, this is the same flow pointed at
`src/content/case-studies/`. Read existing entries
(`smashsend`, `unified`, `weave`, `wisedocs`) to match house style.

## Where things go

| Artifact | Location |
| --- | --- |
| Story body | `src/content/case-studies/<slug>.mdx` (filename IS the slug/route) |
| Cover + inline images | `public/assets/case-studies/<slug>/` |
| Customer logo | `public/assets/logos/<customer>.webp` (or `.svg`) |
| Sitemap entry | `src/app/sitemap.ts` — add `/case-studies/<slug>` in the case-studies block |

The slug is the customer/company name kebab-cased (`weave`, `smashsend`), or the
brief's suggested URL. Confirm with the user if unclear.

## Frontmatter

Open an existing case study and copy its frontmatter shape exactly (fields,
order, naming) rather than inventing keys — the renderer keys off those names.
Typically: `title`, `slug` (must match the filename), `excerpt`/summary, a cover
image path under `/assets/case-studies/<slug>/`, the customer name, and often a
logo, industry, and headline result/metric. Fill every field the existing files
have; if the brief is missing one, note it in the report rather than guessing.

## Converting the brief to MDX

- No H1 in the body — the page renders `title` as the H1. Start the body at the
  first real section.
- Case studies are usually structured as **Challenge → Solution → Results**
  with a pull-quote from the customer and a few headline metrics. Follow the
  structure the existing files use.
- Pull quotes → markdown `> ` blockquote with attribution (name, role, company).
- Metrics/stats → match how existing studies present them (callout numbers or a
  short list); don't invent a component that isn't already used.
- Tables → GFM tables (`<br/>` for in-cell breaks, `&amp;` for `&`).
- Watch for **non-breaking spaces** (U+00A0) pasted from docs — scan with
  `grep -P '\xC2\xA0'` before saving so wrapping doesn't silently change.
- Never copy editorial markers (`[H2]`, highlight notes) into the body.

## Links

- Internal links use relative paths (`/blog/...`, `/case-studies/...`, `/demo`,
  the relevant `/frameworks/...` or `/product/...` page).
- External citations link to the canonical source. Never link to or hotlink
  from `cdn.prod.website-files.com` or any Webflow-hosted URL (Rule 5).
- After publishing, link plain-text mentions of this customer elsewhere if
  appropriate (`grep -rl "<customer>" src/content/`).

## Images

1. Create `public/assets/case-studies/<slug>/`.
2. If the user supplied a cover image, convert/copy it in under the name the
   frontmatter references (prefer `.webp`).
3. If NOT supplied, copy the most topical existing image as a clearly-flagged
   placeholder under the correct name so the page still builds — and warn.
4. Customer logo goes in `public/assets/logos/`. If the logo is shown via a
   component that uses `staticImage()` (not the MDX body), it must ALSO be
   registered in `src/lib/static-images.ts` — see the **swap-image** skill.
5. **Register image dimensions:** run `pnpm manifest` (also runs on
   `pnpm dev` / `pnpm build`). `case-studies/` images are looked up in
   `src/lib/image-dimensions.json` (generated by `scripts/build-image-manifest.mjs`,
   which scans only `blog/` + `case-studies/`). Skip this and the cover image
   silently falls back to an unoptimized `<img>` with layout shift.

## Verify

- `pnpm build` must pass; confirm `.next/server/app/case-studies/<slug>.html`
  exists and the sitemap body contains the new URL. Never build while a
  `pnpm start` server is running.
- `grep -rl "cdn.prod.website-files.com" src/` must not list the new file.

## ⚠️ Required: content completeness report

ALWAYS end with a short report. Check every item; list each failing one with
what's needed to fix it.

- **Cover image** — real image provided, or placeholder? Name the exact file to
  replace.
- **Customer logo** — present and registered (if rendered via `staticImage`)?
- **Title / excerpt / customer / metrics** — any missing from the brief, or
  invented/assumed?
- **Unresolvable links** — referenced pages/posts that don't exist yet.
- **Missing visual assets** — brief-suggested graphics that couldn't be created.
- **Leftover editorial markers / NBSP artifacts** — confirm none made it in.
- **Anything skipped or ambiguous** in the brief.

Do not silently fill gaps: every assumption goes in the report.
